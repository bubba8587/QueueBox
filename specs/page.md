# The page

Rules the board's page keeps. Layout and look details live in `docs/reference.md` and `ui/styles.css`; the words for its parts are in `specs/glossary.md`. Tests: `npm run smoke` (`scripts/smoke.js`) drives the demo board and fails on a console error; no rule below has a test of its own yet.

- **Actions are particular buttons:** an act sits on an icon or labeled button; a row, tile list or other large block is never itself the click target for an act.
- **Open items are always on the map** (author, T27): every lens shows each block's open bugs, tasks and calls
  for the person, so filed work never looks missing. There is no separate Issues lens. Active keeps a block in view
  for open bugs and calls, not for tasks alone.
- **Changes lens:** what hasn't landed, whose, how big and where it collides. Unchanged blocks fade; a changed tile shows its total lines and a bar with one segment per agent, sized by that agent's lines there, in its color, hollow while uncommitted, solid once committed, checked once queued to merge. Where two agents changed the same files the seams between their segments are red and the tile names how many files overlap; a real merge conflict keeps the red tile edge. In a shared checkout each file is credited to the agent who last edited it; the main checkout counts like any worktree. The block's details list each agent's files with their lines.
- **Words:** a block is *reserved* by an agent or *free*; the page, CLI and hooks never say "held".
- **An agent's task line** is the newest of: an item it marked doing or was given ("T4: title"), what it reserved a block for (qb reserve --for, qb next), qb doing --task, and the first line of its latest prompt, a teammate's message unwrapped (a system notice, the board's own wake prompt, or a wordless poke like "." changes nothing).
- **The queue is the team's:** queued blocks and items sit in their own "Up next" window, each entry on its own in queue order: a whole block as its tile (leaving a socket on the map), an item as a row with its block (a button that shows it) and a button that takes it off the queue; a block with only items queued stays on the map. Under the queue a text box files whatever is typed as a task with no block, straight into Up next; its row says No block yet in place of a block button with no person's disc, and the next free agent takes them. The person becomes a block's holder only by an explicit act, "Keep Agents Out" (the block's menu, or the last destination in its details); no drop, default or applied suggestion does it.
- **Size:** one knob, `--ui-scale` in `ui/styles.css`; the map's tile and shelf sizes follow it.
- **Collapse and expand are visual** and per viewer: a collapsed district is one compact tile with its members' badges, each member still reserved on its own. Only districts expand. The district label's chevron collapses and expands; the compact tile itself is not a click target.
- **Shared or per viewer:** where districts sit (`board.layout`, written by dragging a district's label, dropped by Tidy) and which district a block is in are the board's, shared by everyone. Where the map is panned and zoomed to and which districts are collapsed are the viewer's own, kept in the browser.
- **Regrouping is a real board change**, separate from collapse: split a block into sub-blocks from its folders, dissolve a district into one block, move a block between districts. These rewrite `board.json` through one validated write under the store lock and are logged.
- **An item's acts:** an item expanded in the drawer has Done and Won't Fix (Reopen once closed) and Delete, which asks first. Deleting takes an item filed by mistake off the board, its queue place and its asker's open questions included; the log keeps the event, so a replay still shows it, and its id is never given out again. The person, or whoever filed it, deletes it (`qb item <id> delete`).
- **A destination, then Queue:** wherever work can be moved (a block's details, an item row), a dropdown names the destination, General Queue by default, and the Queue button beside it does the moving. The dropdown is never an act by itself and never says "Give To".
- **Quick replies:** a question's popover offers yes, nah, NO WAY, IDK and IDC above its answer box; one press sends that as the answer, the same as typing it and pressing Answer.
- **Now and Lined up:** an agent window splits its work in two. Now holds the blocks it edited in or took in the last 20 minutes and the items it is doing; Lined up holds the rest of what it reserves and the open items given to it. Each item row has its block's button, a destination (General Queue, the default, or another agent) and a Queue button that sends it there; choosing a destination alone does nothing. Sending it to another agent (both are told, and a lined-up block the old agent reserved for it goes along); moving an item it is doing asks first. Return Lined Up, shown while it has something lined up, puts its lined-up items back in Up next unassigned and releases its lined-up blocks; what it is on now stays, and it is told. Report, behind an agent window's chevron, asks the agent to post a board note on what it's on, what's done, what's left and what blocks it. Look Into, on an open item in the drawer, asks a chosen agent (idle ones first) to investigate it without reserving or editing anything and post what it found. Both are messages, so the board wakes an idle background agent for them. Even Out, in Up next's header while an agent with nothing to do could take lined-up work, proposes moving lined-up items from the agents with the most to those with none, one at a time while the giver has more than the taker, keeping an item with an agent that reserves its block unless that agent is working; it shows the moves in a popover and applies them only on Apply, each as a the destination's Queue.
- **The block column:** off phones the drawer is a column of the page left of the map that takes no space until something is open in it: a picked block, or the list of every open item from the Items button in the top bar. Escape or its close button folds it away again (a block opened from the list goes back to the list first), and the map widens back. The list shows every open item on the board, newest first, with chips by kind and a New Item button; each row names its id, who filed it and a button for its block, has its own Queue or Unqueue button, and is marked new when it was filed after the person last had the list open. On a phone it is a sheet that slides up over the page, with a scrim.
- **Timeline height:** a grip centered on the timeline's top edge sets its height, between the time axis with one lane and half the window; the map and side column take the rest, and lanes past the height scroll inside. The arrow keys step it (Shift for larger steps), a double-click on the grip returns the default, and the height is the viewer's own, kept in the browser. The grip is its own handle and hides while the timeline is folded.
- **New code reloads the page:** the page's version is the QueueBox install's commit (its git HEAD, else `package.json`'s version), never a saved file, so pages don't flash on every save or load half-saved code. When the commit changes, the server tells every open page the new stamp; a page on an older one reloads (waiting while a draft is typed, a popover is open or a tile is in hand), keeping its view. A page that connects is told the stamp as it is at that moment.
- **The working dot:** a tile's small blinking dot means someone is working there now: its last edit came in the last three minutes from an agent that is still working. An agent that has gone idle, stopped or left lights no dots.
- **Layout undo:** a change the person makes to where districts sit (a district dragged, Tidy) toasts with Undo; Ctrl+Z undoes the last of them and Ctrl+Shift+Z or Ctrl+Y redoes, up to 20, outside text fields. An undo writes the earlier layout to the board like any change. A change the board refuses leaves the layout as it was.
- **The camera follows Fit:** a camera left where Fit put it frames the map again whenever the map's frame or layout changes; a zoom or a pan by hand keeps it where it was put.
- **The menu bar is Solenoid's:** a thin accent strip above the top bar, its titles in the accent's ink. The first menu is the board's own, named after the repository (Start an Agent, New Item, Items, Settings); then Edit (layout Undo and Redo, Find), View (the lenses, Active blocks only, the timeline, Fit, zoom, Tidy) and Help. Each item runs as its own button or key does; checked items show a tick. A press outside or Escape closes a menu, and pointing at another title with one open switches to it.
- **The top bar is Solenoid's:** a full-width panel at least 44px tall with a hairline under it and the accent as a 2px edge along its bottom; the wordmark takes `--wordmark-color` (the accent in dark, ink in light), and the [Q] mark the accent.
- **The look is Solenoid's theme kit**, vendored in `ui/theme/` and never edited here.
- **One font, Allo**, vendored in `ui/fonts/`, overriding the theme kit's Atkinson pair: tabular figures everywhere and the disambiguation set (`ss02`) where characters are compared; no monospace and no font loaded from outside. The mark is [Q], all in the accent, heavy; the favicon is drawn from Allo Black in the current accent.
- **Subagents are a line, not an agent:** a subagent an agent spawns is one compact row in its parent's window (what it was sent to do, a running timer, then done or failed), fading out a few minutes after it ends. No window, disc, tray or timeline lane of its own. Its tool calls are its parent's work: they count against the parent's reservations and don't move the parent's activity tag.
- **No browser dialogs:** the page never calls the browser's alert, confirm or prompt; only its own toasts, popovers and drawer interrupt.
- **Alerts fire on a change, never on load:** opening the board, or coming back to the tab, notifies nothing that was already true; the first paint primes what has been seen.
- **Typed edits commit on Enter or submit**, never per keystroke; a pick in one gesture (a select, a checkbox) applies at once. An Enter that confirms an input-method candidate is not a commit. Escape closes a long text box and keeps its draft for the next time it opens; in a one-line field it clears the draft.
- **Escape backs out one step:** the open menu, then the popover, then the drawer, then the search, wherever focus is. Settings, when open, goes first.
- **The canvas:** the wheel zooms the map at the cursor, a two-finger trackpad scroll and a Ctrl+wheel pinch included, landing on 10% steps between 20% and 250% (small trackpad deltas add up to a step); it never pans and never zooms the page. Dragging the empty canvas pans; held Space, or the middle button, pans from anywhere on the map, a tile included. The + and − buttons zoom by ×1.4 about the middle, and Fit frames every shown district under the worktree strip, centered, at most 150%, unsnapped. A zoom never set fits the map on load. The dot grid moves and scales with the map. While some of the map is off screen a minimap sits bottom left, drawing each district and the part in view; pressing or dragging on it brings that point to the middle. Below 55% a tile is its name and its color: badges, discs and socket timers go. Right-click on the empty canvas opens its menu: Fit, Zoom to 100%, Tidy, Collapse All and Expand All. A double-click on the canvas does nothing. Two fingers pinch the map off phones: unsnapped, the point between them staying under them, cancelling a pending pan or tile press, and the click a pinch ends on is swallowed; the browser never zooms the page for it.
- **Opaque chrome:** bars, panels, popovers and toasts fill with an opaque surface and never blur what's behind them.
- **Copy:** name the thing and say what it does. No narrated gestures ("Click to …"), no em dashes, no string ending on a parenthetical, American spelling. A tooltip says what a control is, never live data such as a name, a value or an age (not yet: T12, T19). A button's visible label is Title Case ("Ask To Fix"); tooltips and aria-labels are sentence case. A setting's label is a noun phrase; a checkbox's label is the one choice it turns on.
- **Blocked agents need the person:** an agent is blocked when it says so (`qb status blocked`), or when, between turns with nothing in progress, an item assigned to it is marked blocked. Its window reads Blocked, and Needs you gets a row per blocked item with what it waits on (the item's last note), Show (its block) and a message box. A blocked agent is still woken for its messages.
- **Under load the layout holds:** Needs you stays on top of the side column; Up next shows a block's first three queued items and folds the rest under one button ('197 more in Side column'), and scrolls inside a capped height; an agent's Lined up shows its first five and 'N more'. A long list says its true count ('Showing 60 of 1,500') with Show More, and a block's details filter and sort their items; Done is its own folded section with its count. The timeline lists agents holding a block first and scrolls the rest. `scripts/stress.js` writes the board this is checked on (20 agents, 5,000 items in one block, 200 queued, 48,000 events), and the smoke test loads it.
- **Alerts can be dismissed:** each alert in the strip has its own dismiss button; a dismissed alert stays hidden in that browser and for that viewer only. Alerts still go by themselves after three hours.
- **Friendly when quiet:** with every agent idle the canvas says so and offers New Item and Start an Agent; with no agents it offers to start one; a board that has never had one welcomes the viewer and points at Help. It goes as soon as an agent works. `?` opens Help. A block landing raises a short toast ('Basalt landed Map and canvas') as it happens, never on a reload or replay.
